## 🎯 The Google XYZ Formula

Developed by Laszlo Bock (former SVP of People Operations at Google), this is the single most effective framework for writing technical resume bullet points:

$$\text{Accomplished } [\mathbf{X}] \text{ as measured by } [\mathbf{Y}], \text{ by doing } [\mathbf{Z}]$$

### ❌ Weak vs. ✅ Strong Examples

#### Example 1: Backend Performance
* ❌ **Weak:** *"Worked on caching in the backend using Redis."*
* ✅ **Strong (XYZ):** *"Reduced API endpoint latency by 42% (from 320ms to 185ms) by designing a multi-layer Redis caching architecture."*

#### Example 2: Frontend Optimization
* ❌ **Weak:** *"Helped rebuild the web app in React and improved loading times."*
* ✅ **Strong (XYZ):** *"Boosted Lighthouse performance score from 54 to 96 across 12 core pages by code-splitting routes and optimizing asset delivery in React 19."*

#### Example 3: Infrastructure & CI/CD
* ❌ **Weak:** *"Automated tests with GitHub Actions."*
* ✅ **Strong (XYZ):** *"Decreased deployment cycle time from 45 minutes to 8 minutes by implementing parallelized GitHub Actions pipelines with Docker caching."*

## ⚡ Strong Action Verbs Cheat Sheet

Always start every bullet point with a decisive, past-tense action verb. Avoid weak phrases like *"Responsible for..."*, *"Assisted with..."*, or *"Worked on..."*.

### 🏗️ Building & Engineering
`Architected` &bull; `Built` &bull; `Constructed` &bull; `Developed` &bull; `Engineered` &bull; `Implemented` &bull; `Pioneered` &bull; `Programmed`

### ⚡ Optimization & Performance
`Accelerated` &bull; `Audited` &bull; `Automated` &bull; `Consolidated` &bull; `Decreased` &bull; `Eliminated` &bull; `Maximized` &bull; `Minimized` &bull; `Optimized` &bull; `Refactored` &bull; `Streamlined`

### 🛡️ Reliability & Scale
`Centralized` &bull; `Configured` &bull; `Deployed` &bull; `Integrated` &bull; `Migrated` &bull; `Modernized` &bull; `Overhauled` &bull; `Re-architected` &bull; `Scaled` &bull; `Standardized` &bull; `Upgraded`

### 👥 Collaboration & Leadership
`Championed` &bull; `Coordinated` &bull; `Directed` &bull; `Guided` &bull; `Headed` &bull; `Led` &bull; `Mentored` &bull; `Orchestrated` &bull; `Spearheaded`

## 🛠️ Skills Categorization Best Practices

Technical skills should be structured logically by category. This makes it effortless for hiring managers to match requirements in seconds.

### Recommended Grouping:

```
Languages:        C++, TypeScript, Python, Go, Java, SQL
Frameworks:       React, Node.js, Express, Next.js, FastAPI, Spring Boot
Developer Tools:  Git, Docker, Kubernetes, AWS, Linux, GitHub Actions, Redis
Coursework:       Data Structures & Algorithms, Operating Systems, Database Systems, Computer Networks
```

### 🚫 What NOT to Do:
- **No Rating Bars:** Do not write *"Python: 85%"* or display 4 stars. What does 85% in Python even mean?
- **No Obvious Tools:** Do not list *VS Code, Windows, Slack, Microsoft Word, Zoom* as core technical skills.
- **No Fluffy Soft Skills:** Do not list *Team Player, Fast Learner, Hard Worker, Good Communicator* in your skills section. Demonstrate these through project impact instead.

## ⚠️ The Disqualification Checklist

Before hitting download, review your resume against these critical disqualification factors:

- [ ] **Exact 1 Page:** Does your resume fit cleanly onto 1 page without trailing lines on page 2?
- [ ] **Comma & Spacing:** Did you place a space after every comma and period? (e.g. `React, TypeScript` NOT `React,TypeScript`).
- [ ] **Consistent Dates:** Are all dates formatted uniformly (e.g., `Sep. 2023 – Jun. 2024` or `Jun. 2025 – Present`)?
- [ ] **Active Links:** Do your GitHub and LinkedIn links open valid URLs?
- [ ] **Searchable Plain Text:** Can you press `Ctrl+F` in the exported PDF to find keywords like `Java` or `Docker`?
- [ ] **Proofread:** Have at least 2 peers or native English speakers proofread your bullet points?
